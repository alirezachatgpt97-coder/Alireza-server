## 🅰️ معرفی پروژه

**alirezaserver** یک لایه ادغام روی **Nova Server** است. نوا پایه پنل باقی می‌ماند و دو بخش جدید به محیط مدیریت اضافه می‌شوند:

- 🛡️ **DNS · AdGuard Home:** دسترسی به رابط اصلی AdGuard برای مدیریت DNS، فیلترها و گزارش درخواست‌ها.
- 🔐 **OpenVPN:** ساخت سرور، مدیریت حساب‌ها، تعیین حجم و تاریخ انقضا و دریافت فایل اتصال.

🎨 نام نمایشی پنل به **alirezaserver** تغییر می‌کند و نشان **A** جای نشان نوا را می‌گیرد. رنگ‌های بخش AdGuard با محیط پنل هماهنگ می‌شوند. لینک‌های شبکه‌های اجتماعیِ بخش مشخص‌شده در رابط نوا غیرفعال می‌شوند و آیکون‌ها باقی می‌مانند.

🧩 فایل‌های اصلی نوا در این ادغام بازنویسی نمی‌شوند. نام سرویس‌ها، مسیرهای داخلی و متغیرهای فنی `NOVA_*` برای حفظ سازگاری باقی می‌مانند؛ بنابراین دیدن نام Nova در مسیر فایل‌ها یا ابزارهای مدیریتی سیستم طبیعی است.

📌 **یکپارچگی این نسخه در رابط مدیریت است:** حساب‌ها و آمار OpenVPN در پایگاه داده جداگانه ذخیره می‌شوند و به کاربران، اشتراک‌ها و حسابداری بومی نوا تبدیل نمی‌شوند.

### 📍 مواردی که باید از ابتدا بدانید

- افزونه‌ها روی **سرور اصلی پنل** نصب می‌شوند؛ به همه نودهای نوا منتقل نمی‌شوند.
- مدیریت OpenVPN این پروژه اقتباسی از تنظیمات و الگوهای `vpn-ui` است؛ کل پنل vpn-ui و سایر پروتکل‌های آن نصب نمی‌شوند.
- OpenVPN به اشتراک بومی نوا، نمایندگی‌ها، ربات تلگرام، حسابداری نودها و تولید پل نوا متصل نشده است.
- ترافیک OpenVPN از مسیر IPv4 میزبان خارج می‌شود؛ خودکار وارد خروجی‌های سفارشی Xray یا WARP نوا نمی‌شود.
- رابط اصلی AdGuard حفظ می‌شود، اما هر قابلیت وابسته به شبکه، مثل DHCP یا شنونده‌های رمزگذاری‌شده DNS، پیش‌نیاز و تنظیمات خودش را دارد.

## 🚀 نصب با یک دستور

### ۱. 👑 وارد محیط root شوید

اگر با root وارد نشده‌اید:

```bash
sudo -i
```

### ۲. 📥 نصب تک‌خطی از مخزن رسمی پروژه

```bash
curl -fL --retry 3 https://raw.githubusercontent.com/alirezachatgpt97-coder/alirezaserver/main/setup.sh -o alirezaserver-setup.sh && bash alirezaserver-setup.sh
```

✅ این دستور ابتدا دانلود را کامل می‌کند و فقط در صورت موفقیت دریافت، راه‌انداز را اجرا می‌کند. فایل `alirezaserver-setup.sh` در پوشه فعلی باقی می‌ماند تا برای بررسی، پشتیبان‌گیری یا ترمیم دوباره از آن استفاده کنید.

اگر `curl` نصب نیست:

```bash
apt-get update && apt-get install -y ca-certificates curl
```

### ۳. ⏳ مراحل نصب را تا انتها دنبال کنید

نصب شامل این مراحل است:

1. 📦 دریافت نسخه مشخص نصب‌کننده و بررسی صحت فایل.
2. 🛡️ آماده‌سازی AdGuard پیش از نصب پایه نوا، تا خطای دریافت آن پشت پیام نصب نوا پنهان نماند.
3. 🖥️ نصب نوا یا بررسی نسخه موجود؛ سؤال‌های تنظیم اولیه نوا در همین مرحله نمایش داده می‌شوند.
4. 🎨 نصب تغییرات برند و فایل‌های مدیریت DNS و OpenVPN.
5. ⚙️ فعال‌سازی سرویس‌ها و اتصال افزونه به فرایند نوا.
6. 🔍 بررسی رابط و APIها، دسترسی مالک، مسیر HTTPS و پاسخ DNS.

### 🟢 نشانه پایان موفق نصب

تا مشاهده این پیام صبر کنید:

```text
ALIREZASERVER READY
```

**نمایش پیام «نوا آماده است» در میانه نصب، به معنی تکمیل alirezaserver نیست.** نشانی پنل، رمز اولیه و اطلاعات ورود را هنگام نصب نگه دارید.

### 📄 نصب مستقیم بدون راه‌انداز

اگر فقط فایل اصلی را می‌خواهید:

```bash
curl -fL --retry 3 https://raw.githubusercontent.com/alirezachatgpt97-coder/alirezaserver/main/install.sh -o alirezaserver-install.sh && bash alirezaserver-install.sh
```

این مسیر فایل فعلی شاخه `main` را اجرا می‌کند. مسیر `setup.sh` به یک نسخه مشخص متصل است و صحت نصب‌کننده را با SHA-256 کنترل می‌کند.

### 🔎 فقط دریافت و بررسی فایل

```bash
bash alirezaserver-setup.sh --download-only
```

در این حالت نصب آغاز نمی‌شود. نسخه تأییدشده در این مسیر قرار می‌گیرد:

```text
/var/cache/alirezaserver/install-0.3.0.sh
```

📌 در حال حاضر راه‌انداز به نسخه **0.3.0** متصل است؛ به‌روزرسانی فایل‌های دیگر مخزن باعث اجرای خودکار نصب‌کننده متفاوت نمی‌شود.

## ⚙️ تنظیمات اختیاری هنگام نصب

متغیرهای زیر را در همان محیط root که نصب را اجرا می‌کنید تنظیم کنید. اگر نیازی به مقدار سفارشی ندارید، از نصب معمولی استفاده کنید.

| متغیر | کاربرد |
| --- | --- |
| `NOVA_DOMAIN` | دامنه مورد استفاده در تنظیم اولیه نوا؛ باید به سرور اشاره کند |
| `NOVA_PANEL_PATH` | مسیر مخفی پنل؛ `none` یعنی بدون مسیر مخفی |
| `NOVA_PANEL_PORT` | پورت HTTPS اضافی مخصوص پنل، مطابق قابلیت نصب‌کننده نوا |
| `NOVA_FRONT_PORT` | پورت جلویی نوا در تنظیم اولیه، به‌جای مقدار معمول ۴۴۳ |
| `NOVA_NO_PROMPT` | مقدار `1` برای استفاده از مقادیر محیط و پیش‌فرض‌ها بدون سؤال تعاملی |
| `DNS_ALLOWED_CIDRS` | IP یا شبکه‌های مجاز DNS، جداشده با کاما، برای تنظیم اولیه |

### 🌍 نمونه تنظیم دامنه

```bash
NOVA_DOMAIN='panel.example.com' bash alirezaserver-setup.sh
```

### 🛡️ نمونه مجازکردن یک IP برای DNS

```bash
DNS_ALLOWED_CIDRS='203.0.113.10/32' bash alirezaserver-setup.sh
```

### 🌐 نمونه چند IP یا شبکه

```bash
DNS_ALLOWED_CIDRS='203.0.113.10/32,198.51.100.0/24' bash alirezaserver-setup.sh
```

📝 آدرس‌ها و دامنه‌های نمونه را با اطلاعات واقعی جایگزین کنید. این متغیر DNS برای **ایجاد تنظیمات اولیه** است؛ اجرای دوباره نصب، فهرست سفارشی دسترسی AdGuard را بازنویسی نمی‌کند؛ فقط فهرست پیش‌فرض خصوصی نسخه قدیمی اصلاح می‌شود. بعد از نصب، تغییرات را از داخل AdGuard اعمال کنید.

2. 🔑 با اطلاعات ورود نوا وارد شوید.
3. 🅰️ نام `alirezaserver` و نشان A را در رابط بررسی کنید.

5. 🔐 برای مدیریت اتصال‌های جدید، وارد **OpenVPN** شوید.
6. ↩️ با دکمه بازگشت، به محیط اصلی پنل برگردید.

👑 گزینه‌های افزوده‌شده مخصوص **مالک پنل** هستند. اگر با حساب نماینده وارد شده‌اید، نبود این گزینه‌ها لزوماً اشکال نصب نیست.

🔒 اگر نصب بدون دامنه انجام شده باشد، نوا می‌تواند از گواهی خودامضا استفاده کند و مرورگر هشدار گواهی نشان دهد. نشانی را با سرور خودتان تطبیق دهید؛ تنظیم دامنه و گواهی معتبر موضوع جداگانه‌ای است.

🔎 برای پیدا کردن مجدد نشانی پنل، ابزار اصلی نوا در دسترس است:

```bash
nova-access
```

## 🛡️ مدیریت DNS با AdGuard Home

### 🧩 نحوه دسترسی

روی **DNS · AdGuard Home** کلیک کنید. رابط اصلی AdGuard در همان محیط مدیریت باز می‌شود و از نشست مالک نوا استفاده می‌کند. پورت وب داخلی AdGuard به‌صورت پیش‌فرض برای اینترنت باز نمی‌شود.

### 📊 داشبورد

برای بررسی تعداد درخواست‌ها، درخواست‌های مسدودشده، کلاینت‌های فعال و وضعیت پاسخ‌گویی DNS از داشبورد AdGuard استفاده کنید. آمار واقعی بعد از آن ظاهر می‌شود که یک دستگاه درخواست DNS را به این سرور بفرستد.

### 🧱 فیلترها

فهرست‌های مسدودسازی و قواعد دلخواه را از بخش فیلترهای خود AdGuard مدیریت کنید. در نصب اولیه، فیلتر DNS ادگارد فعال است. اگر دامنه موردنیاز یک برنامه مسدود شد، Query Log را بررسی کرده و قاعده یا استثنا را متناسب با همان دامنه اصلاح کنید.

### 📜 گزارش درخواست‌ها

بخش **Query Log** برای دیدن دامنه درخواستی، کلاینت و نتیجه پردازش استفاده می‌شود. برای تشخیص یک مشکل، ابتدا از دستگاه موردنظر یک درخواست جدید ایجاد کنید و سپس گزارش همان زمان را بررسی کنید.

### 🌍 سرورهای بالادستی

در تنظیمات DNS، بخش **Upstream DNS servers** را مدیریت کنید. تنظیم اولیه از DNS معمولی کلادفلر (`1.1.1.1`) و Quad9 (`9.9.9.9`) استفاده می‌کند. دسترسی سرور شما به این آدرس‌ها اهمیت دارد؛ بالا بودن سرویس AdGuard به‌تنهایی تضمین دسترسی به اینترنت یا upstream نیست.

### 🚪 پورت و آدرس شنود

| مورد | تنظیم اولیه |
| --- | --- |
| پورت DNS | **53** |
| انتقال | **UDP و TCP** |
| آدرس‌ها | `127.0.0.1` و IPv4 انتخاب‌شده از مسیر پیش‌فرض سرور |
| رابط وب داخلی | `127.0.0.1:18085` |
| دسترسی مدیریتی | از داخل پنل و با نقش مالک |

🔌 شنونده مستقیم IPv6 یا سرویس عمومی DoH/DoT به‌صورت خودکار آماده نمی‌شود. وجود گزینه‌های آن‌ها در AdGuard به معنی پیکربندی دامنه، گواهی و پورت‌های مربوط نیست.

### 👥 اجازه دسترسی به DNS

در نصب تازهٔ نسخه 0.3.0، DNS روی IPv4 سرور و پورت 53 برای کلاینت‌های عمومی فعال است؛ محدودیت نرخ AdGuard برابر 20 درخواست در ثانیه است. برای محدودکردن دسترسی به دستگاه‌های مشخص:

1. وارد **Settings → DNS settings → Access settings** شوید.
2. IP عمومی دستگاه، روتر یا شبکه موردنظر را به فهرست مجاز اضافه کنید.
3. دسترسی **UDP/53 و TCP/53** را در فایروال سرویس‌دهنده VPS نیز بررسی کنید.
4. DNS دستگاه را روی آدرس سرور تنظیم کنید.
5. درخواست آزمایشی بفرستید و نتیجه را در Query Log ببینید.

📌 اگر IP اینترنت شما تغییر می‌کند، فهرست دسترسی نیز باید متناسب با آن مدیریت شود. فهرست Allowed clients خالی یعنی پذیرش کلاینت‌های عمومی؛ با واردکردن IP یا شبکه، دسترسی را محدود می‌کنید.

### 🧪 آزمایش پاسخ DNS

روی دستگاهی که `dig` دارد و IP آن مجاز است:

```bash
dig @YOUR_SERVER_IP example.com
dig +tcp @YOUR_SERVER_IP example.com
```

`YOUR_SERVER_IP` را با IP واقعی سرور جایگزین کنید. یکی از دستورها UDP و دیگری TCP را آزمایش می‌کند.

<a id="openvpn"></a>

## 🔐 ساخت سرور OpenVPN

### ۱. ➕ افزودن سرور

از منوی **OpenVPN**، گزینه **افزودن سرور** را انتخاب کنید.

| فیلد | توضیح و نمونه |
| --- | --- |
| 🏷️ نام | عنوان قابل تشخیص؛ مثل `Main OpenVPN` |
| 🌍 آدرس عمومی | IP یا دامنه‌ای که کاربر از اینترنت به آن متصل می‌شود؛ `127.0.0.1` برای کاربران بیرونی مناسب نیست |
| 🚀 انتقال | `UDP` یا `TCP`، مطابق نیاز شبکه و کلاینت |
| 🚪 پورت | پورت آزاد از `1024` تا `65535`؛ مثلاً `1194` |
| 🕸️ شبکه کاربران | یک شبکه خصوصی `/24` بدون تداخل؛ مثلاً `10.231.10.0/24` |
| 🛡️ DNS کاربران | آدرس DNS قابل دسترس؛ برای نمونه بالا، `10.231.10.1` می‌تواند به AdGuard همین سرور هدایت شود |
| 📦 MTU | مقدار مجاز `1280` تا `1500`؛ مقدار اولیه `1500` |
| 👥 حداکثر اتصال | سقف اتصال‌های همان سرور؛ محدود به توان واقعی میزبان نیز هست |
| 🔑 رمزنگاری | انتخاب از گزینه‌های موجود در فرم با توجه به سازگاری کلاینت |
| 🛡️ TLS-Crypt | حفاظت از کانال کنترل؛ در تنظیم اولیه فعال است |
| 🔁 ارتباط کاربران | اجازه ارتباط کاربران همان سرور با یکدیگر؛ پیش‌فرض غیرفعال |

### ۲. 💾 ذخیره و بررسی

هنگام ذخیره، اطلاعات ورودی، تداخل شبکه و اشغال‌بودن پورت بررسی می‌شود. گواهی‌ها ساخته و سرویس همان سرور راه‌اندازی می‌شود. اگر سرویس آماده نشود، خطا نمایش داده می‌شود؛ گزارش همان سرور را بررسی کنید.

🔄 ویرایش تنظیمات سرور می‌تواند اتصال کاربران همان سرور را قطع و دوباره برقرار کند. این کار را در زمان مناسب انجام دهید.

### ۳. 📥 دریافت فایل اتصال

فایل `.ovpn` را از گزینه **فایل اتصال** دریافت کنید. این فایل شامل تنظیمات سرور و اطلاعات لازم برای اتصال است؛ نام کاربری و رمز عبور جداگانه هنگام اتصال وارد می‌شوند.

### ۴. 📱 اتصال دستگاه

1. فایل `.ovpn` را در برنامه سازگار با OpenVPN وارد کنید.
2. نام کاربری و رمز حسابی را که در همین بخش ساخته‌اید وارد کنید.
3. اتصال را برقرار کنید.
4. وضعیت دستگاه آنلاین، مصرف و دسترسی واقعی به اینترنت را بررسی کنید.

📍 مسیر خروج اینترنت در این ادغام IPv4 است. تنظیمات پروفایل برای مسدودکردن ترافیک IPv6 خارج از تونل در نظر گرفته شده‌اند؛ رفتار واقعی را روی کلاینت مورد استفاده نیز آزمایش کنید.

## 👥 مدیریت حساب‌های OpenVPN

ابتدا حداقل یک سرور بسازید، سپس **افزودن حساب** را انتخاب کنید.

| تنظیم | رفتار |
| --- | --- |
| 👤 نام کاربری | ۱ تا ۶۴ نویسه از حروف انگلیسی، عدد و علامت‌های `_ . @ -` |
| 🔑 رمز عبور | ۱۲ تا ۱۲۸ نویسه؛ هنگام ساخت حساب الزامی است |
| 📊 سهمیه | برحسب GB ده‌دهی؛ هر GB برابر یک میلیارد بایت، مقدار صفر یعنی نامحدود |
| 📅 انقضا | تاریخ و ساعت پایان دسترسی؛ خالی یعنی بدون تاریخ انقضا |
| 📱 دستگاه هم‌زمان | از ۱ تا ۶۴، با توجه به نیاز و منابع سرور |
| 🖥️ سرورهای مجاز | انتخاب سرورهایی که حساب اجازه اتصال به آن‌ها را دارد |
| ✅ فعال | فعال یا غیرفعال‌بودن حساب |

### 🛠️ عملیات حساب

- ✏️ **ویرایش:** تغییر رمز، سهمیه، انقضا، سقف دستگاه و سرورهای مجاز.
- 🔑 **حفظ رمز قبلی:** در ویرایش، فیلد رمز را خالی بگذارید.
- ⏸️ **غیرفعال‌کردن:** دسترسی حساب را متوقف می‌کند.
- 🔄 **صفرکردن مصرف:** مصرف ثبت‌شده حساب را صفر می‌کند؛ سهمیه تعریف‌شده جداست.
- 🗑️ **حذف:** حساب را از مدیریت OpenVPN حذف می‌کند.

📝 نام کاربری پس از ساخت قابل تغییر نیست؛ برای نام جدید حساب تازه بسازید. تغییر حساب، اتصال‌های فعلی آن را قطع می‌کند تا تنظیمات جدید اعمال شوند.

⏱️ آمار و اجرای محدودیت حجم به‌صورت دوره‌ای انجام می‌شود، نه برای تک‌تک بسته‌های شبکه. نزدیک سقف مصرف، مقداری اختلاف به‌دلیل فاصله نمونه‌برداری ممکن است وجود داشته باشد.

📌 این حساب‌ها **مستقل از حساب‌های نوا** هستند. ساخت کاربر در نوا به‌صورت خودکار حساب OpenVPN ایجاد نمی‌کند و برعکس.

<a id="nodes"></a>

## 🧩 نودها و اتصال‌های اصلی نوا

بخش افزودن نود همچنان از سازوکار اصلی نوا استفاده می‌کند. دستور تولیدشده توسط پنل را بدون تغییر نام متغیرها یا آدرس‌های فنی، روی سرور مقصد اجرا کنید.

- 🔗 متغیرهای `NOVA_JOIN_URL`، `NOVA_JOIN_TOKEN` و اطلاعات مربوط به اتصال نود حفظ می‌شوند.
- 🧱 تغییر نام ظاهری پنل، نام پروتکل‌ها یا ساختار اتصال نود را تغییر نمی‌دهد.
- 🖥️ افزونه‌های DNS و OpenVPN این نسخه روی میزبان اصلی پنل قرار دارند.
- 📌 انتظار نصب خودکار AdGuard و مدیریت مستقل OpenVPN روی تمام نودهای اضافه‌شده را نداشته باشید.

<a id="ports"></a>

## 🚪 پورت‌ها و فایروال

| سرویس | پورت | محل دسترسی |
| --- | --- | --- |
| 🌐 ورودی HTTPS نوا | معمولاً `443` یا پورت انتخاب‌شده | عمومی |
| 🛡️ DNS | `53/UDP` و `53/TCP` | روی IPv4 سرور، با فهرست دسترسی AdGuard |
| 🔐 OpenVPN | انتخابی؛ مثلاً `1194/UDP` | بعد از ساخت و فعال‌کردن سرور |
| 🖥️ HTTP داخلی نوا | معمولاً `8088` | داخلی؛ متناسب با تنظیم نوا |
| ⚙️ وب داخلی AdGuard | `18085/TCP` | فقط لوپ‌بک |
| 🧰 SSH | پورت تنظیم‌شده سرور شما | برای مدیریت VPS |

🧱 افزونه قوانین خود را در زنجیره‌های `ALIREZA_*` قرار می‌دهد و زنجیره‌های اصلی فایروال را پاک نمی‌کند. بازشدن پورت روی خود لینوکس، فایروال پنل شرکت میزبان یا Security Group را تغییر نمی‌دهد.

📌 پورت داخلی AdGuard را برای دسترسی مستقیم به اینترنت باز نکنید؛ مسیر مدیریتی آماده‌شده، بخش DNS داخل پنل است.

## 💾 پشتیبان‌گیری

### 📦 پشتیبان افزونه‌ها

```bash
bash alirezaserver-setup.sh --backup
```

یا بدون نیاز به فایل راه‌انداز:

```bash
python3 /opt/alirezaserver/backup.py
```

آرشیو با تاریخ و ساعت در این مسیر ساخته می‌شود:

```text
/var/backups/alirezaserver/
```

پشتیبان شامل نسخه سازگار پایگاه داده افزونه، حساب‌ها، گواهی‌ها، تنظیمات AdGuard، فایل‌های ادغام و تعریف سرویس‌هاست.

### 🖥️ پشتیبان نوا

از ابزار پشتیبان‌گیری خود نوا نیز استفاده کنید. **پشتیبان نوا و پشتیبان افزونه‌ها جای یکدیگر را نمی‌گیرند.** برای نگهداری کامل، هر دو را به محل مطمئنی خارج از همان VPS منتقل کنید.

🔐 آرشیو افزونه حاوی اطلاعات حساس و کلیدهاست؛ آن را عمومی نکنید. بازیابی خودکار با دستور `--restore` در این نسخه وجود ندارد و بازگردانی باید با توجه به مسیرها، نسخه‌ها و مالکیت فایل‌ها انجام شود.

## 🔍 بررسی سلامت و گزارش‌ها

### ✅ بررسی یک‌جای سرویس‌ها

```bash
bash alirezaserver-setup.sh --check
```

یا:

```bash
bash /opt/alirezaserver/check.sh
```

این بررسی، وضعیت سرویس‌ها، پورت DNS، دسترسی مالک به رابط و API افزونه‌ها، تغییر برند و مسیر محلی HTTPS پنل را ارزیابی می‌کند. برای آزمایش DNS، در صورت فعال‌بودن قابلیت Rewrite، یک رکورد موقت ایجاد و پس از تست TCP/UDP حذف می‌شود.

🌍 پاسخ‌گویی DNS بالادستی نیز جداگانه بررسی می‌شود. در دسترس‌نبودن upstream به‌صورت هشدار گزارش می‌شود و افزونه‌های سالم را خودکار حذف نمی‌کند.

📌 موفقیت بررسی محلی جای تست اتصال OpenVPN از یک دستگاه بیرونی، دسترسی اینترنتی پورت‌ها یا آزمایش بار را نمی‌گیرد.

```bash
ls -lt /var/log/alirezaserver/
```

## 🔄 ادامه نصب ناقص، ترمیم و نسخه‌ها

### 🛠️ ترمیم نصب

```bash
bash alirezaserver-setup.sh --repair
```

اجرای معمولی راه‌انداز نیز وارد همان مسیر نصب/ترمیم می‌شود. تنظیمات موجود DNS، پایگاه داده کاربران و گواهی‌های افزونه حفظ می‌شوند. برای داده شناخته‌شده نسخه قبلی، پیش از ترمیم پشتیبان گرفته می‌شود.

🧩 نیازی نیست برای هر خطای نصب، سیستم‌عامل سرور را پاک کنید. ابتدا مرحله خطا و گزارش نصب را بررسی کنید، علت را برطرف کنید و همان راه‌انداز را دوباره اجرا کنید.

### 🏷️ تفاوت ترمیم با ارتقا

`--repair` به معنی ارتقای خودکار نوا به آخرین نسخه نیست. راه‌انداز فعلی، نصب‌کننده **0.3.0** را از شاخه main با هش محتوای مشخص دریافت می‌کند. به‌روزرسانی مستقل نوا یا AdGuard می‌تواند نیازمند بررسی دوباره سازگاری ادغام باشد.

📦 قبل از ارتقا، از داده‌های نوا و افزونه‌ها پشتیبان بگیرید و توضیحات نسخه جدید پروژه را بخوانید.

<a id="rollback"></a>

## ↩️ غیرفعال‌کردن افزونه‌ها و بازگشت به اجرای اصلی نوا

```bash
bash alirezaserver-setup.sh --rollback
```

این دستور:

- ⏹️ سرویس‌های OpenVPN ساخته‌شده توسط افزونه و سرویس AdGuard را متوقف/غیرفعال می‌کند.
- 🧱 قوانین اختصاصی فایروال افزونه را برمی‌دارد.
- 🧩 بارگذاری افزونه در سرویس نوا را حذف می‌کند.
- 🔄 سرویس اصلی نوا را دوباره راه‌اندازی می‌کند.
- 💾 فایل‌ها، پایگاه داده و گواهی‌های افزونه را برای بازیابی نگه می‌دارد.

**این دستور حذف کامل نوا یا پاک‌کردن همه داده‌ها نیست.** قطع سرویس DNS یا VPN روی دستگاه‌هایی که از آن استفاده می‌کنند اثر می‌گذارد.

## ⚡ منابع و عملکرد

هدف ادغام، اضافه‌کردن قابلیت‌ها بدون راه‌اندازی یک پنل کامل اضافی vpn-ui است. افزونه داخل فرایند موجود نوا بارگذاری می‌شود؛ AdGuard و هر سرور OpenVPN سرویس‌های مستقل خود را دارند.

- 🧠 سقف heap فرایند نوا در تنظیم راه‌اندازی این نسخه `192 MB` است؛ این عدد سقف کل RAM مصرفی سیستم یا حتی کل حافظه همان فرایند نیست.
- 🛡️ برای حافظه Go در AdGuard مقدار نرم `160 MiB` در نظر گرفته شده؛ این مقدار حد سخت مصرف نیست.
- 🗃️ داده‌های افزونه در SQLite محلی نگهداری می‌شوند.
- 📊 آمار OpenVPN دوره‌ای جمع‌آوری می‌شود و صفحه مدیریتی هنگام پنهان‌بودن مرتب درخواست وضعیت نمی‌فرستد.
- 🎨 امکانات و جزئیات گرافیکی پنل برای کاهش مصرف حذف نشده‌اند.

روی VPS کم‌منبع، مصرف RAM، فضای دیسک و گزارش‌های سرویس را زیر بار واقعی بررسی کنید. تعداد زیاد کاربران، چندین سرور OpenVPN و فهرست‌های بزرگ DNS به منابع بیشتری نیاز دارند. ظرفیت ثابت یا اجرای بدون افت تحت هر بار کاری ادعا نمی‌شود.

</details>

</details>
